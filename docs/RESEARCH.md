# Научная постановка

Этот файл описывает, **какой исследовательский вопрос здесь можно задать и чем он отличается от «ещё одного сканера»**. Это план для работы, а не сама работа и не результат: числа и выводы нужно получить заново на данных, которые автор работы собирает сам.

## Вопрос

> По журналу сессии агента, насколько точно можно приписать опасное действие недоверенному источнику, и в каких случаях это принципиально невозможно?

Две части:
1. **Атрибуция.** Для действия `a` и набора прочитанных агентом текстов `T` определить, какие `t ∈ T` на него повлияли. Журнал даёт только порядок событий и тексты, а не «мысли» модели, поэтому честная постановка это *происхождение данных* (provenance), а не причинность.
2. **Границы.** Класс атак, у которых в журнале нет следов (подмена самого агента, пакета, слов «пользователя»), нельзя найти ни одним методом по журналу. Нужно описать этот класс формально и показать на примерах.

## Что уже есть в репозитории

- **Модель событий** (`ectoplasm/model.py`, `transcript.py`): пользователь, контекст клиента, вызовы и результаты инструментов, ранг доверия источника.
- **Методы атрибуции** (`trace.py`): происхождение адресов, происхождение чувствительных путей, признаки инструкции в тексте, «тройка» (недоверенный текст, доступ к данным, отправка наружу), снятие подозрений новым сообщением пользователя.
- **Данные** (`dataset/ectoplasm-bench-v1`): 75 синтетических сессий с разметкой и карточкой набора. Автор один, сессии короткие, поэтому для работы нужны другие данные (см. ниже).
- **Границы описаны примерами**: 4 заведомо невидимых случая (`limit`), 1 пропуск в наборе `hard`, разбор десяти публичных кейсов в `docs/CASES.md`.

## Что нужно сделать, чтобы это стало исследованием

1. **Данные без автора-разметчика.** Журналы реальных агентских сессий (с согласия, без личных данных) или сценарии, написанные другими людьми. Две независимые разметки и согласие между ними (коэффициент Коэна κ) вместо одного автора.
2. **Метрики.** Для атрибуции: precision и recall на уровне действий; для границ: доля атак, у которых в журнале нет ни одного следа. Отдельно сообщать результаты на подборочной и отложенной частях.
3. **Базовые уровни для сравнения.** «Любое опасное действие после недоверенного текста» (самый простой), только поиск ключевых фраз, только «тройка», полный набор; опционально судья-модель (`--judge-cmd`).
4. **Угрозы валидности** (честно описать): синтетичность данных, один автор, знание правил при написании тестов, короткие сессии, язык (русский и английский), один формат журнала.
5. **Теория границ.** Формализовать «журнал-наблюдаемость» атаки: атака наблюдаема, если существует текст в журнале, из которого её действие выводится как функция. Показать невозможность для атак через код инструмента и подмену промпта.

## Связь с языковыми моделями

Самая естественная линия: заменить признаки инструкции в тексте на оценку модели (`--judge-cmd` уже принимает любую команду), измерить прирост recall на перефразированных атаках (`hard`) и цену в ложных срабатываниях. Вопросы: как отличить инструкцию, адресованную агенту, от текста о таких инструкциях (статья про prompt injection), и устойчив ли судья сам к инъекции.

## Чего здесь нет

Нет результатов, нет сравнения с чужими методами, нет оценки на реальных атаках. Цифры в README относятся к синтетическому набору и оптимистичны. Писать работу должен её автор: этот файл только фиксирует постановку и то, что уже можно воспроизвести.
