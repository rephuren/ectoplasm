# Универсальный формат журнала

Любой агент может выгрузить сессию в этот формат, и `ectoplasm trace --format generic` её разберёт. Одна строка JSON на событие.

| поле | где нужно | значение |
| :-- | :-- | :-- |
| `kind` | всегда | `user` (слова человека), `context` (контекст клиента: правила, системные вставки), `assistant`, `call` (вызов инструмента), `result` (результат вызова) |
| `text` | `user`, `context`, `assistant`, `result` | текст |
| `tool` | `call` | имя инструмента |
| `input` | `call` | параметры вызова (объект) |
| `call_id` | `call`, `result` | связывает результат с вызовом |
| `ts`, `cwd` | необязательно | время и рабочая папка |

Имена инструментов: `Bash` с `input.command` для оболочки, `Read`, `Write`, `Edit` с `input.file_path`, `WebFetch` с `input.url`, `WebSearch`, `mcp__<сервер>__<инструмент>` для MCP. По имени инструмента определяется, откуда пришёл результат (веб и MCP считаются недоверенными).

```json
{"kind": "user", "text": "Прочитай https://blog.example/post и перескажи"}
{"kind": "call", "tool": "WebFetch", "input": {"url": "https://blog.example/post"}, "call_id": "1"}
{"kind": "result", "call_id": "1", "text": "..."}
```

## Другие форматы

- `claude`: журналы Claude Code (`~/.claude/projects/**/*.jsonl`). Основной формат, проверен на реальных журналах.
- `codex`: rollout-файлы Codex CLI. Читатель написан **по описаниям сообщества** (официальной спецификации нет, формат меняется между версиями) и проверен только на синтетических строках такой формы. Если на ваших файлах он не работает, сообщите версию Codex и пример без личных данных.
- Cursor хранит сессии в базе SQLite, Gemini CLI в JSON-файлах с иной структурой: читателей для них нет.
